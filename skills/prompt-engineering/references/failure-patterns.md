# Prompt 翻车模式与修法

自检清单。写完一个 prompt,逐条对照;命中的就按右边修。

## 格式类(最常见)

| 翻车模式 | 症状 | 修法 |
|---|---|---|
| 没给输出格式 | 输出飘、每次结构不一样 | 给精确 schema/模板,贴一个期望输出样本 |
| 要 JSON 却收到 markdown 代码块 | 输出带 ```json 包裹,解析报错 | 明确"只输出 JSON,不要代码块、不要解释";放最后说 |
| 字段名/大小写不稳 | key 时有时无、大小写乱 | 在 schema 里写死字段名,示例里用同样的写法 |
| 长度失控 | 该短的长、该长的短 | 给硬数字:"不超过 3 条""每条 ≤20 字""至少 500 字" |

## 指令类

| 翻车模式 | 症状 | 修法 |
|---|---|---|
| 全是形容词没动作 | 模型不知道具体干啥 | 每条指令动词开头(输出/列出/拒绝/拆解) |
| 否定指令堆叠 | "不要不要不要",模型照犯 | 改成正面:"只做 Y";否定只做补刀 |
| 约束冲突 | "简洁"又"详细解释",模型二选一 | 消歧:"给一句话结论 + 3 条要点,不展开论证" |
| 约束埋在长段落里 | 模型抓不住 | 约束单独成节,用列表/编号 |
| 指令离输出位置太远 | 结尾的格式要求被忽略 | 把最关键的格式指令放在 prompt 末尾、紧邻输出 |

## 示例类

| 翻车模式 | 症状 | 修法 |
|---|---|---|
| 没有 few-shot | 风格/边界猜不准 | 补 1-3 个 输入→期望输出 对 |
| 示例风格互相矛盾 | 模型学到混乱信号 | 统一所有示例的输出风格/详略 |
| 示例太少覆盖不了边界 | 遇到边缘输入就崩 | 补反例/边界示例 |

## 角色类

| 翻车模式 | 症状 | 修法 |
|---|---|---|
| 角色是装饰 | 身份很长但不服务任务 | 砍到一句"你是 X,擅长 Y";删掉"温柔体贴全知全能" |
| 角色带入过度 | 模型把角色台词带进输出 | 明确"身份只影响你如何思考,不要在输出里自称或扮演角色" |

## 边界类

| 翻车模式 | 症状 | 修法 |
|---|---|---|
| 没说歧义怎么办 | 模型硬编一个答案 | 加:"信息不足时,列出缺什么并提问,不要猜" |
| 没说不合规怎么办 | 被诱导绕过/瞎配合 | 加:"输入违反 X 时,拒绝并说明原因" |
| 没说工具用完怎么办 | 工具结果不被利用就结束 | 加:"调用工具后,必须基于返回结果回答,不要无视" |

## 参数类

| 翻车模式 | 症状 | 修法 |
|---|---|---|
| 创意任务用低温度 | 输出死板重复 | 提到 0.7+ |
| 抽取/分类用高温度 | 格式飘、胡编 | 降到 0~0.3 |
| max_tokens 太小 | 输出被截断 | 调大或改 prompt 更精简 |

## 通用自检三问

1. 把 prompt 给一个**没上下文的人**看,他能照着做出期望输出吗?不能 → 约束/格式不清。
2. 输入换成**边界/刁钻**情况,模型知道怎么办吗?不知道 → 缺边界处理和反例。
3. prompt 里有没有**互相矛盾**的要求?有 → 消歧。
