# 长文结构模板

五种最常见的长文结构。先选对结构,文章成了一半。每种给骨架 + 适用场景 + 展开要点。

---

## 1. 观点文(Opinion)— "我认为 X,因为 Y"

**适用**:表达主张、挑战共识、输出立场。公众号/专栏/社论常见。

**骨架**:
```
[钩子:一个反常识的现象 / 痛点 / 故事]
→ 我的核心观点(一句话,早点抛)
→ 论据 1(数据 / 案例 / 逻辑)
→ 论据 2
→ 论据 3(最好有一个"反面论证 + 反驳",显出想过)
→ 所以呢:这个观点对你意味着什么 / 怎么做
[结尾:一句能被记住的话]
```

**要点**:
- 观点必须明确、有立场。"这事儿有好有坏"不是观点。
- 每个论据都要能独立支撑观点,不是凑数。
- 主动写反方观点并反驳,比回避更有说服力。

---

## 2. 教程 / How-to — "怎么做 X,从零到能跑"

**适用**:手把手教一项技能/操作。技术博客、操作指南。

**骨架**:
```
[钩子:学完你能做到什么 / 不学的痛点]
→ 前置:你需要准备什么 / 已有什么前提
→ 步骤 1:做 X(为什么这一步 + 具体怎么做 + 可能踩的坑)
→ 步骤 2:...
→ 步骤 N:...
→ 验证:怎么知道做对了(可运行的结果/检查点)
→ 下一步:进阶方向 / 常见问题
```

**要点**:
- 每一步都可复现:有命令、有代码、有截图位。
- 标注"为什么会这样",不只是"输入这个"。
- 把常见报错和解决提前写进去(读者会搜到的坑)。

---

## 3. 深度分析(Analysis)— "X 到底是怎么回事,拆给你看"

**适用**:拆解一个复杂现象/产品/技术/事件。调研型长文。

**骨架**:
```
[钩子:这个事为什么值得搞清楚]
→ 背景:它是什么、怎么来的(简短)
→ 拆解维度 1(如:技术层面)
→ 拆解维度 2(如:商业层面)
→ 拆解维度 3(如:影响层面)
→ 交叉分析:这几个维度怎么互相作用
→ 判断:基于拆解,我的结论 / 趋势预测
```

**要点**:
- 拆解维度要 MECE(互斥穷尽),不是想到哪写到哪。
- 给数据和事实支撑,不要空泛判断。
- 结论必须从拆解中长出来,不是硬塞。

---

## 4. 经验复盘(Learnings)— "我做完了 X,这些是踩过的坑和学到的"

**适用**:项目复盘、踩坑总结、个人经验输出。

**骨架**:
```
[钩子:这件事的背景 + 结果(成或败)]
→ 情境:我面对的是什么
→ 关键决策点 1:我怎么选的、为什么、结果如何
→ 关键决策点 2:...
→ 复盘:哪些做对了 / 哪些错了 / 如果重来会怎么改
→ 可迁移的经验:对读者有什么用
```

**要点**:
- 真实 > 完美。承认做错的地方最有价值。
- 具体到决策和动作,不是"要努力""要坚持"。
- 经验要抽象到可迁移,不只停留在"我的故事"。

---

## 5. 清单 / Listicle — "N 个 X,每个都管用"

**适用**:易于传播、信息密度高的盘点。注意:别为了凑数注水。

**骨架**:
```
[钩子:为什么这 N 个值得看 / 筛选标准]
→ 条目 1(标题 + 一段解释 + 例子/用法)
→ 条目 2
→ ...
→ 条目 N
[结尾:怎么挑适合自己的 / 一个速查索引]
```

**要点**:
- 每条独立成立,有具体价值(不是"要专注""要自律"这种废话)。
- 条目之间尽量 MECE 或有清晰排序逻辑(难度递进/重要性)。
- 宁可 5 条干货,不要 20 条水货。

---

## 选结构的快速判断

| 用户要写的是 | 选哪个 |
|---|---|
| 我想说服别人接受一个看法 | 观点文 |
| 教别人一步步做某事 | 教程 |
| 把一个复杂东西讲清楚 | 深度分析 |
| 分享我做某事的经验教训 | 经验复盘 |
| 盘点一堆有用的东西 | 清单 |

**混合**:大结构选一种,内部章节可借用其他结构(如深度分析里某节用教程展开)。

## 通用质量线(任何结构都要过)

- 每章都服务核心观点,不服务的删。
- 每段一个观点,段首即观点句。
- 每个判断有证据(数据/案例/逻辑),不是空断言。
- 删掉所有"正确的废话"。
