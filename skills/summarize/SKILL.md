# 智能总结

你的任务:把长内容压缩成**分层、保真、可行动**的总结。用户给一大段东西,要的是"几分钟拿到全部要点,且不会被骗"。

铁律:**只压缩,不臆造。** 没说的不要编,数字/人名/结论必须忠实于原文;拿不准的标"存疑",绝不脑补。

## 何时用

- 长文章 / 网页 / PDF / 论文 / 报告 → 要点提取。
- 会议 / 访谈 / 播客转写 → 议题 + 决议 + 行动项。
- 视频字幕 / 直播文字稿 → 内容精简。
- 聊天记录 / 邮件串 → 抽结论和待办。
- 代码文件 / PR → 做了什么、为什么。

## 何时别用

- 内容本来就短 → 直接读,不用总结。
- 要逐字翻译 → 用 `translate`。
- 要深度多源研究 + 自己查证 → 用 `deep-research`(总结只处理用户给的一份材料)。
- 要把材料改写成文章/博客 → 用 `write-blog`。

## 三个原则

1. **分层产出,不是一段平铺。** 一句话 TL;DR → 关键要点 → 细节/数据。让用户随时停在某一层就够用。
2. **保真优先,压缩其次。** 宁可多留一条,不可漏关键或瞎编。数字、专有名词、因果结论一个不能错。
3. **分类型施策。** 文章、会议、论文、代码、视频的"要点"长得不一样,套对应的结构(见 references)。

## 工作流

### 1. 先判断材料类型与用户目标

类型决定结构(文章=论点论据;会议=议题决议行动项;论文=问题方法结论;代码=做了什么为什么;视频=脉络亮点)。

同时判断用户要"多详细":
- 只要结论 → 给 TL;DR + 关键点。
- 要能转述给别人 → 加上脉络和关键数据。
- 要决策/行动 → 加重行动项和风险。

### 2. 通读全文(别跳读)

先整体读一遍建立全貌,再回头提炼。**跳读是漏要点和误判因果的主因。**

### 3. 分层产出

按这个骨架(按材料类型从 references 选模板微调):

```
## 一句话总结(TL;DR)
<30-50 字,这篇东西最核心的一句话>

## 关键要点(3-7 条)
- <每条一个完整论点/事实,带关键数据>
- ...

## 值得注意 / 存疑
- <矛盾处、没说清的、需要核实的>(没有就省略这节)

## 行动项(如有)
- [ ] <谁> <做什么>(材料里没有明确行动项就明确说"材料未涉及可执行行动项",别编)
```

### 4. 回头核对(关键步骤)

写完逐项核对:
- **数字 / 日期 / 人名 / 专有名词** → 和原文一致?
- **因果 / 结论** → 是原文说的,还是我推断的?推断的要标"推断"。
- **有没有漏掉**改变结论的关键信息?

### 5. 标存疑,不脑补

材料里没讲清的、自相矛盾的、需要外部知识核实的 → 列进"存疑",诚实告诉用户"这一点材料没说 / 有矛盾",让用户自己决定。

## 失败模式(别犯)

- ❌ **臆造**:编原文没有的细节、数字、因果。最严重,绝对禁止。
- ❌ **平铺一大段**:不分层、无重点,等于把长文压缩成短文,用户还是抓不住。
- ❌ **漏关键**:砍太狠,丢了改变结论的信息。
- ❌ **保留冗余**:把客套/重复/离题内容也总结进来,稀释要点。
- ❌ **把"我觉得"当成材料说**:夹带自己的观点或外部知识而不标注。
- ❌ **统一模板套所有类型**:会议总结套文章模板,行动项就丢了。
- ❌ **没有 TL;DR**:直接上要点列表,用户连"要不要细看"都没法快速判断。

## 长材料处理

材料特别长时(整本书、几万字):
- 先出**章节地图**(每章一句话),让用户挑想细看的部分。
- 再对用户关心的部分做要点级总结。
- 主动问"要不要对某一部分展开",而不是一次性倒一大堆。

## 输出格式

按上面的骨架。务必带 TL;DR。行动项不存在就明说,不要硬凑。最后附一句"如需展开某点或要更短/更详细版本,告诉我"。
