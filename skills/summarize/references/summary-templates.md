# 分类型总结模板

每类材料"要点"长得不一样。按材料类型选模板,套用并微调。每个模板给结构和示例。

---

## 1. 文章 / 博客 / 报道

**核心:论点 + 论据 + 结论。**

```
## TL;DR
<一句话:作者最想让你信/知道的事>

## 核心论点
- <主论点>
## 关键支撑
- <证据/数据/案例 1>
- <证据/数据/案例 2>
## 作者结论 / 主张
- <结论>
## 存疑 / 反面
- <没说清的、有争议的、可反驳的>
```

**示例要点写法**:
- ✅ "作者主张远程办公提升产出 13%,依据是斯坦福对携程 16 个月的对照实验。"
- ❌ "远程办公更好。"(丢了依据,无法判断可信度)

---

## 2. 会议 / 访谈 / 播客转写

**核心:议题 + 决议 + 行动项,不要流水账。**

```
## TL;DR
<一句话:这场会定了什么 / 达成了什么>

## 议题与决议
- 议题 A:<一句话议题> → 决议:<决定了什么>(未定则写"未达成共识")
- 议题 B:...

## 行动项
- [ ] <谁> 在 <何时前> 做 <什么>(没指派/没截止就标"待定")

## 关键分歧 / 遗留
- <谁和谁在什么上不一致 / 挂起没解决的>

## 没涉及
- <明显该谈但没谈的>(可选)
```

**纪律**:
- 流水账(谁说了啥)→ 删。只留议题、决议、行动项。
- 没有明确结论的议题,标"讨论未果/延期",别编一个结论。
- 行动项缺负责人或截止,标"待定",不要自己分配。

---

## 3. 论文 / 学术报告

**核心:问题 → 方法 → 结果 → 意义 + 局限。**

```
## TL;DR
<一句话:这篇论文用 X 方法解决了 Y 问题,得到 Z 结果>

## 研究问题
- <要回答的问题>
## 方法
- <数据 / 实验设计 / 模型>(关键参数)
## 主要结果
- <定量结果 + 关键数字>
## 贡献 / 意义
- <为什么重要>
## 局限 / 未来工作
- <作者承认的局限>
## 存疑
- <样本量够吗?因果还是相关?可复现吗?>(你的批判性存疑)
```

**纪律**:数字原样保留;p 值、效应量、样本量是判断可信度的关键,别省。

---

## 4. 代码 / PR / Commit

**核心:做了什么 + 为什么 + 影响。**

```
## TL;DR
<一句话:这次改动做了什么>

## 改了什么
- <模块/文件>:<行为变化>(新增 / 修改 / 移除)
## 为什么
- <动机:修了什么 bug / 加了什么能力 / 为什么重构>
## 影响与风险
- <可能影响的下游 / 兼容性 / 已知风险>
## 测试 / 验证
- <加了什么测试 / 怎么验的>(没有就标"未附测试")
## 存疑
- <看起来可疑 / 需要人确认的地方>
```

**纪律**:读 diff 提炼,不要逐文件罗列。把"做了什么"按逻辑分组,不是按文件。

---

## 5. 视频 / 直播 / 播客(非访谈型)

**核心:脉络 + 亮点,不要时间轴流水账。**

```
## TL;DR
<一句话:这个视频讲了什么>

## 主要脉络
- <阶段 1:讲了什么>
- <阶段 2:讲了什么>
## 关键亮点 / 干货
- <值得记的点 / 金句 / 反常识结论>
## 可跳过
- <整段跑题 / 推广 / 重复>(帮用户省时间)
## 存疑
- <说错了 / 有争议的 / 没说清的>
```

---

## 6. 邮件串 / 聊天记录 / 讨论帖

**核心:问题 + 各方立场 + 结论 + 待办。**

```
## TL;DR
<一句话:这串讨论最后定了/解决了什么>

## 背景
- <最初的问题/诉求>
## 各方立场
- <人/方 A>:<主张>
- <人/方 B>:<主张>
## 结论 / 共识
- <达成了什么>(没达成写"未定")
## 行动项
- [ ] <谁> <做什么>
## 存疑
- <没回复的 / 悬而未决的>
```

---

## 通用:压缩档位

用户没明说要多详细时,默认"标准档"(TL;DR + 要点)。可按需切换:

| 档位 | 何时用 | 产出 |
|---|---|---|
| 极简 | 用户只想知道要不要细看 | 一句话 TL;DR + 3 条要点 |
| 标准(默认) | 通用速读 | TL;DR + 关键要点 + 存疑 + 行动项 |
| 详细 | 要转述/汇报 | 标准 + 脉络 + 关键数据 + 引用 |

主动问用户"要更短还是更详细",而不是自己猜。
