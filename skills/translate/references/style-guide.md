# 中英互译文体指南 & 机翻味清单

## 一、机翻味清单(英译中)

命中就改。左边是典型机翻味,右边是地道写法。

| 机翻味 | 地道写法 |
|---|---|
| "作为一个开发者,你需要..." | "开发者在……时" / 直接"要……" |
| "它是非常重要的" | "它很重要"(删掉"是...的") |
| "在...的情况下" | "若…""…时" |
| "对于...来说" | 重写句子,把主语放前面 |
| "被...所..."(滥用被动) | 中文多用主动,补泛指主语"有人/大家/把" |
| "...的...的...的"(定语链过长) | 拆成短句,把长定语改成补充说明 |
| "在这个领域中,我们提出了一种方法" | "我们提出了一种方法"(删空壳句) |
| "信息"→information 永远译"信息" | 看语境:消息/资料/情报/通知 |
| "实现"→implement 永远译"实现" | 实现/落实/执行/开发,看语境 |
| 滥用"性/化"(可扩展性、规范化) | 能拆就拆:"容易扩展""统一标准" |
| "进行"+动词("进行分析") | 直接用动词:"分析" |
| "有关...的" | "...的"或重写 |

**通用诊断**:读出声,像不像中国人自然说的话?不像就有翻译腔。

## 二、机翻味清单(中译英)

| 机翻味 | 地道写法 |
|---|---|
| "It is very important for..." 开头 | 主语前置:"X matters because..." |
| 滥用 "very / really / so" | 删掉,或换更准的形容词 |
| "We should pay attention to..." | "Note that..." / "Watch for..." |
| 长串 "and" 连接 | 用从句、分号、断句 |
| 动词全用 "make / do / get" | 换精准动词(generate/build/yield) |
| 中式英文 "open the light" | "turn on the light"(搭配备查) |
| "Chinese style" 正式套话直译 | 意译,或删(英文不爱客套) |

**通用诊断**:母语者会不会这么说?动词搭配(collocation)对不对?

## 三、文体对照(按场景定调)

| 场景 | 中文调性 | 英文调性 |
|---|---|---|
| 技术文档 | 简洁、直接、无歧义,多用祈使 | 同左;短句,主动语态为主 |
| 学术论文 | 严谨、术语规范、长句允许 | 正式、被动可接受、hedging(may/suggest) |
| 营销文案 | 有感染力、口语化、短促 | punchy、active、benefit-driven |
| 商务邮件 | 礼貌但不啰嗦 | polite but concise,避免过度客套 |
| UI 文案 | 极简、动词化、留出长度余量 | 同左;title case vs sentence case 看平台规范 |
| 字幕 | 口语、短句、可读性优先 | spoken、short、punchy |

## 四、术语处理规则

1. **先定后用,全程一致。** 开工前建术语表,首次出现锁定译法。
2. **产品名/品牌名**:有官方译名用官方;没有就保留原文(尤其英文产品名在中文里不译)。
3. **技术术语**:
   - 有约定俗成译法用约定(如 recursion→递归,inference→推理)。
   - 争议术语(如 prompt→提示词/提示语/指令):选一个并保持一致,首次出现可附原文。
   - 新词/无定译:保留原文 + 首次加注,后续用译法或原文。
4. **人名/地名**:知名用通用译法;生僻保留原文,不硬音译。
5. **缩写**:首次"全称(缩写)",后续直接用缩写;广泛认知的缩写(API/URL)直接用。
6. **数字/单位/日期**:数字照搬不转换(1,500 → 1500,注意千分位习惯);单位按目标地区习惯(磅/千克可加注);日期格式按目标语言习惯。

## 五、格式保留清单

这些必须原样保留、位置不动:

- Markdown:`#`、`-`、`|表格|`、`代码块`、链接 `[text](url)`、图片。
- 占位符:`{{name}}`、`%s`、`{0}`、`$1`、`<tag>` —— **名字不译,位置不动**。
- 代码、命令、文件名、URL、邮箱。
- 列表层级、缩进、换行节奏。
- HTML 标签(只译标签里的文本内容)。
