# 四维审查 checklist

每个维度独立过一遍,不要混着扫。命中即记录:位置(文件:行) + 维度 + 初步严重度(Step 4 再校准)。

## 一、正确性(Correctness)

- [ ] 逻辑 bug:条件取反、循环边界 off-by-one、break/continue 误用、三元运算嵌套歧义
- [ ] 边界条件:空集合、空字符串、0、负数、最大值、首尾元素
- [ ] 空值处理:None/null/nil/undefined 返回值是否判空;可选链是否遗漏;默认值是否合理
- [ ] 并发竞态:共享变量无保护、check-then-act 非原子、伪单例持有可变状态
- [ ] 资源泄漏:文件/连接/锁/游标是否在异常路径也释放(try-finally / defer / using)
- [ ] 异常处理:catch 了不处理(吞异常)、catch 范围过大、异常类型不匹配
- [ ] 状态机:状态流转是否合法、是否有非法跳转、终态后是否仍可操作
- [ ] 返回值忽略:写操作返回的影响行数、异步结果、错误码是否检查

## 二、安全性(Security)

- [ ] SQL 注入:字符串拼接 SQL(检查 f-string、模板字符串、`+` 拼接);确认是否参数化
- [ ] XSS:用户输入未转义直接渲染 HTML/JS;`dangerouslySetInnerHTML` / `v-html`
- [ ] 命令注入:`system` / `exec` / `subprocess(shell=True)` 接用户输入
- [ ] 越权(IDOR):按 ID 查资源是否校验归属;是否只验登录不验权限
- [ ] 认证授权:接口是否需要登录却没校验;权限检查是否仅在前端
- [ ] 敏感信息:密码/密钥/token 是否硬编码、是否打日志、响应是否泄露
- [ ] 依赖漏洞:已知 CVE 依赖、过时框架、不安全加密(MD5/DES 存密码)
- [ ] 文件上传:类型校验、路径穿越(`../`)、大小限制、可执行权限

## 三、性能(Performance)

- [ ] N+1 查询:循环里查数据库;ORM 关联懒加载在循环里触发
- [ ] 复杂度:嵌套循环 O(n²) 及以上、全表扫描、O(n) 可 O(1) 的查找(改 dict/set)
- [ ] 内存:大结果集一次性 load、无分页、大对象长期持有缓存不释放
- [ ] 重复计算:循环内不变量可提出、同一查询多次调用
- [ ] 大查询:`SELECT *`、无 LIMIT、WHERE 条件未命中索引、JOIN 缺索引(怀疑时跑 `EXPLAIN` 验证,见下方红绿灯)
- [ ] 锁阻塞:长事务、锁内做 IO/远程调用、慢查询持锁
- [ ] 资源耗尽:线程池/连接池配置过小、无超时导致连接堆积

### EXPLAIN 红绿灯(MySQL,国内绝对主流,必会解读)

怀疑某条 SQL 慢时,让它跑一遍 `EXPLAIN`,按下面两张表判红黄绿。两张表都要看:type 决定"扫描方式",Extra 决定"额外代价"。

**`type` 列(扫描方式)**

| type | 信号 | 含义 / 动作 |
|------|------|------------|
| `system` / `const` | 🟢 绿 | 表最多一行 / 主键等值命中,最优 |
| `eq_ref` | 🟢 绿 | JOIN 用上主键/唯一索引等值,最优 JOIN |
| `ref` / `ref_or_null` | 🟢 绿 | 走普通索引等值,可接受 |
| `range` | 🟡 黄 | 索引范围扫描,看扫描行数,大范围要警惕 |
| `index` | 🟡 黄 | 扫整棵索引树(比 ALL 好,但仍全扫),通常需优化 |
| `ALL` | 🔴 红 | 全表扫描,生产表必须优化 |

**`Extra` 列(额外代价)**

| Extra | 信号 | 含义 / 动作 |
|-------|------|------------|
| `Using index` | 🟢 绿 | 覆盖索引,不用回表,理想 |
| `Using where` | 🟢 绿 | 在存储引擎返回后做过滤,正常 |
| `Using index condition` | 🟢 绿 | 索引条件下推(ICP),优化过的回表,可接受 |
| `Using filesort` | 🔴 红 | 额外排序,大数据量拖垮,看 `ORDER BY` 是否走索引 |
| `Using temporary` | 🔴 红 | 用了临时表(GROUP BY / DISTINCT / UNION 常见),高并发下危险 |
| `Using join buffer` | 🟡 黄 | JOIN 没走索引走块嵌套,补 JOIN 列索引 |

**索引失效清单(看上去有索引但实际没用上,必须逐条排查)**

- [ ] **列上套函数**:`WHERE DATE(create_time)=...` / `WHERE UPPER(name)=...` → 索引失效。改为等值/范围,或建函数索引 / 生成列索引。
- [ ] **隐式类型转换**:`WHERE phone=13800000000`(varchar 列传数字)→ 索引失效。参数类型与列类型一致(字符串列传 `'138...'`)。
- [ ] **LIKE 前导通配**:`WHERE name LIKE '%abc'` → 索引失效。前导通配改全文索引或 ES;`LIKE 'abc%'` 才走索引。
- [ ] **OR 连接非索引列**:`WHERE a=1 OR b=2`,若 b 无索引则整查询退化为全表扫。要么 b 也建索引,要么拆 UNION。
- [ ] **复合索引非左前缀**:索引 `(a,b,c)` 只查 `b` 或 `c` 不走索引;必须从 `a` 开始连续命中。
- [ ] **`!=` / `<>` / `NOT IN`**:多数情况不走索引(优化器成本判断),大表改写为范围或反向 IN。
- [ ] **`IS NULL` / `IS NOT NULL`**:取决于占比与优化器,大表上常失效,必要时建部分索引。

## 四、可维护性(Maintainability)

- [ ] 命名:是否达意、是否误导(`funclist` 存 dict)、是否统一风格
- [ ] 重复代码:复制粘贴的逻辑(超 ~10 行)、应抽函数/基类
- [ ] 耦合:隐式依赖全局状态、跨层调用(Controller 直连 DAO)、循环依赖
- [ ] 可读性:函数过长(>80 行)、嵌套过深(>4 层)、参数过多(>5)
- [ ] 魔法数字/字符串:散落的未命名常量、应抽常量/枚举
- [ ] 注释:复杂逻辑无注释、注释与代码不符(过时)、废话注释
- [ ] 单一职责:一个函数/类干太多事、改动理由过多

> **维度边界**:正确性查"对不对",安全查"能不能被利用",性能查"快不快",可维护查"好不好改"。同一问题跨维时(如 N+1 既是性能也潜在正确性隐患),按主要影响归一维,避免重复报。
