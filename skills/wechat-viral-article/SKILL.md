# 公众号爆款长文

把"写公众号长文"从玄学变成 SOP。输入一个主题,产出可直接复制到公众号后台的成稿,并附 10 个标题候选、金句清单、排版说明与引流设计。核心价值不是替你写字,而是把 10w+ 文章背后那套**选题—标题—结构—情绪—金句—排版—引流**的工业化打法固化进流程,让每一篇都按爆款骨架生成,而不是从空白文档开始硬憋。

适用场景:公众号推文、品牌深度内容、知识付费引流文、个人 IP 长文、行业盘点。适合 1500-5000 字的中长文场景。

---

## 核心方法论

这套方法论是本 skill 的卖点,每一条都直接决定成稿质量,必须贯彻到每一篇产出中。

### 1. 标题是公众号的生死线——决定打开率

公众号自 2022-2023 起已全面信息流推荐化,推荐流量已成为多数账号阅读量的主战场(常读 + 订阅 + 推荐三分天下),但**标题(及封面)仍是信息流中决定点击的生死线**——在推荐池里被划过,后面结构再好都白搭。一个好标题与差标题的点击率可以相差数倍甚至一个数量级(经验观察,非精确数据)。建议把标题当作独立产物反复打磨:行业内常说"标题值一篇文章 20% 的精力"(经验值,供参考),本 skill 强制产出 10 个候选做 AB 测试、标注所用公式(见下),就是把这个环节做实,而不是给 1-2 个让你将就。

| 公式 | 触发心理 | 适用场景 |
| --- | --- | --- |
| 悬念反差 | 好奇缺口 | 反常识、揭秘类 |
| 数字清单 | 确定感、省事 | 盘点、方法论、教程 |
| 共情痛点 | "说的就是我" | 情感、职场、成长 |
| 争议/反常识观点 | 站队、争论 | 观点、行业评论 |
| 利益承诺 | 收益明确 | 干货、教程、理财 |
| 人物故事 | 代入感 | 人物稿、案例 |
| 热点借势 | 蹭流量 | 时效话题 |
| 对比冲击 | 反差震撼 | 盘点、对比评测 |
| 钩子前置 + 二次反转 | 二次好奇缺口 | 信息流高打开,深度观点 |
| 具体场景 + 反直觉结论 | 反常识 + 代入 | 第一人称实验体、个人经历 |

> 后两条是 2024-2026 公众号信息流推荐机制下流行的高打开结构,前 8 条为经典公式。

详见 `templates/title-ab-test.md`。

### 2. 长文万能结构:凤头·猪肚·豹尾

公众号长文(2000 字以上)最容易死在"开头没抓住,中段没递进,结尾没升华"。强制使用三段式骨架:

- **凤头(开头,占 10-15%)**:3 种开篇法任选其一——故事切入 / 反常数据 / 犀利提问。**3 句话内必须勾住读者**,否则直接划走。
- **猪肚(主体,占 70%)**:分 3-5 个小标题推进,每段一个明确观点,配案例 / 故事 / 数据支撑。**每个小标题都要能独立成立**,因为很多读者只扫小标题。
- **豹尾(结尾,占 15%)**:升华 + 金句 + CTA。不要总结,要**留余味**,给读者一个转发的理由。

详见 `templates/structure-template.md`。

### 3. 情绪曲线——完读率的命脉

平铺直叙的长文必死。读者在手机上读 2000 字,需要**情绪起伏**牵引他往下滚。强制为每段标注情绪点,形成曲线:

```
情绪
 高 │          ╭──╮            ╭───(升华)
    │         ╱    ╲          ╱
    │   ╭──╮╱      ╰──╮   ╭──╱
    │  ╱    ╲        ╲ ╱  ╱
 低 │╭─╯     ╲        ╳  ╱
    ╰┷┷┷┷┷┷┷┷┷┷┷┷┷┷┷┷┷┷┷┷┷┷┷→ 段落
     开头  认同  惊讶  共鸣  信任  高潮转折  结尾
```

> 纯文字版(防手机/非等宽字体错位):**波峰**→开头(好奇/痛点)、惊讶(反常识小高峰)、共鸣(戳心)、高潮转折(全文最震撼)、升华;**波谷**→认同、信任(叙事铺陈段)。全文至少 2 个波峰,平铺必死。

典型曲线:**抓人(好奇/痛)→ 认同 → 惊讶 → 共鸣 → 信任 → 高潮转折 → 升华**。每段结尾留"钩子"(一个未解的问题、一句悬念)牵引下一段。

### 4. 金句引擎——转发系数的来源

金句不是装饰,是**传播引擎**。读者转发一篇文章,很大程度上就是冲着里面那句话——金句本身就是传播单元。每篇至少嵌 3-5 句可独立传播的金句,放在**小标题、段末高潮、结尾升华处**(不要堆在某一段)。

金句四要素(至少满足两条):短句、对仗、反差、洞察。详见 `templates/golden-quotes.md`。

### 5. 选题角度发散——不写"正确而无聊的话"

同一话题至少给出 3-5 个角度,选**最有冲突感和信息增量**的那一个。常见角度类型:

| 角度类型 | 冲突强度 | 适合 |
| --- | --- | --- |
| 痛点型 | 高 | 情感、职场、生活 |
| 反常识型 | 很高 | 观点、科普、行业 |
| 方法论型 | 中 | 干货、教程 |
| 人物故事型 | 高 | 案例、采访 |
| 盘点对比型 | 中 | 行业、评测 |

永远不要默认第一个想到的角度。**正确而无聊的角度是长文最大的浪费。**

### 6. 排版规范——移动端深度阅读

公众号是少数还能做深度阅读的场景,但手机屏幕小,大段文字仍会劝退。强制遵循:

- 短段落:**手机 3-5 行/段**(约 60-100 字),超长段落必须拆。
- 小标题分行:**每个小标题独占一行,加粗**。
- 关键句加粗:全文 3-5 处,**用粗体标出关键句/金句**(不要滥用,加粗多了等于没加粗)。
- 配图节点:长文建议每 600-800 字一个配图位,标注 `[配图建议:...]`。
- 留白:段落间空一行,小标题前后留白。

详见 `templates/formatting-guide.md`。

### 7. 引流转付费——植入而非硬塞

公众号长文的商业价值在文末。硬广割裂感会伤完读率和好感,但完全不引流等于浪费流量。强制使用**自然过渡式引流**:文末话题延伸到"如果想更系统了解/想和同频的人交流/想要 XX 工具",再给 CTA。提供引流话术模板,详见 `templates/formatting-guide.md`。

## 工作流程

按以下 8 步顺序执行,每步都有明确产出,不得跳过。

### Step 0 解析输入

读取用户输入,提取以下字段;缺失的字段**主动追问或合理推断**,不要凭空编造:

| 字段 | 是否必须 | 说明 |
| --- | --- | --- |
| 主题 | 必须 | 文章核心话题 |
| 账号定位 | 推荐 | 决定语气、专业度、人设 |
| 目标人群 | 推荐 | 决定选题角度、痛点切入 |
| 字数区间 | 推荐 | 默认 2500(区间 2000-3000) |
| 是否引流 | 可选 | 默认"是,但自然植入" |

同时读取用户环境中的长期偏好(全局 `CLAUDE.md`、或本目录下 `_config.json`,字段见末尾【配置】一节),获取账号人设、禁用词、引流话术等;没有就用默认值,**不强依赖**项目级配置文件存在。

### Step 1 选题角度发散

针对主题,列出 3-5 个角度(参考方法论第 5 条),用表格对比冲突强度和信息增量,**选出 1 个并说明理由**(为什么选它、不选其他的理由)。

产出格式:

```
## 选题角度
| 角度 | 类型 | 冲突强度 | 信息增量 |
|------|------|---------|---------|
| ... | ... | ... | ... |
选定:<角度>。理由:...
```

### Step 2 标题 AB 测试(10 选 3)

用 10w+ 标题 8 公式 + 2 条 2024-2026 信息流新增结构(钩子前置二次反转、具体场景反直觉结论)生成 **10 个候选标题**,每个标注所用公式(详见 `templates/title-ab-test.md`),从打开率、调性匹配、平台风险三维度评估,**推荐 Top 3** 并说明理由。标题是独立产物,值得反复打磨(行业内常说占一篇文章 20% 的精力,经验值供参考)。

### Step 3 定结构 + 情绪曲线

套用凤头猪肚豹尾骨架(详见 `templates/structure-template.md`):

1. 确定开头法(故事切入 / 反常数据 / 犀利提问)。
2. 列主体 3-5 个小标题(每个一句话写出本段核心观点)。
3. 设计结尾升华点 + CTA。
4. 为每段标注情绪点,画出情绪曲线,确保有起伏而非平铺。

产出:一份结构大纲(小标题 + 情绪标注)。

**关于"先过目再写正文"的执行模式(单轮 gate 规则,必读)**:
- **单次产出模式(默认,不中断)**:用户一次性给出主题+字数、本次执行中没有可往返交互的对话通道(典型:脚本/一次性 prompt 调用本 skill)时,**必须连续跑完 Step 4→7 一次交付完整成稿,不得在 Step 3 停下等用户确认**。"先过目"降级为:在最终交付物里把结构大纲作为一块附上即可。
- **分段确认模式(需显式触发)**:仅当处于多轮对话、**且用户本轮明确说**"先看大纲""分段写""等我确认再继续""先给结构"等字样时,才在 Step 3 产出大纲后停下,把球交回用户。
- **判断不准时的 fallback**:默认走单次产出模式,宁可一次给全也不要卡死——卡死等一个不会来的确认,是最差的产出失败。
- 也就是说:"可选"不是 agent 自己猜要不要停,而是**由交互模式 + 用户显式指令共同决定**,缺一不可。

**判断算例(照此套,不靠猜,消除"该不该停"的歧义)**:
- **场景 A(单次产出,默认,不停)**:用户一次给完"主题 + 字数 + 定位"就不再说话;或你在一次性脚本/无往返通道的环境里被调用。→ Step 3 大纲作为一块附在最终交付物里,**连续跑完 Step 4→7,不在 Step 3 停**。
- **场景 B(分段确认,需显式触发,才停)**:多轮对话中,用户本轮明确说"先看大纲""分段写""等我确认再继续""先给结构"等字样。→ Step 3 产出大纲后停下,把球交回用户,等确认再进 Step 4。
- **场景 C(拿不准)**:无法判断是否多轮 / 用户没明说。→ **默认按 A 走**(宁可一次给全,不卡死等一个不会来的确认)。
- 铁律:停与不停**不取决于 agent 的偏好**,只取决于"有无交互通道 + 用户是否显式要求分段"两个客观条件同时成立。

### Step 4 写正文

按结构大纲成文。每段:小标题 + 观点 + 案例/故事/数据支撑 + 段末钩子。遵循排版规范(短段、加粗、配图节点)。字数对齐用户要求(默认 2500,区间 2000-3000)。

> **案例/数据写入正文的守则(与"边界情况→数据真实性"配套)**:写到人物案例时,凡是带具体数字(年限/金额/涨幅/结果)的,要么改写成无数字的现象描写写进正文,要么把具体数字挪到【发布前待填/待核】区并标 `[示例数据]`,正文只留现象叙述——**不得把编造数字直接白描成"真人真事",也不得把 `[示例数据]` 标、`(示例数据,发布前核实)` 这类待核标注写进正文**(它们只属于【发布前待填/待核】区);写到统计数字时同理:有来源(经 WebSearch 核实)才进正文,否则进待核区。

**【字数口径定义(强制,全文统一,杜绝"约 N 字"虚标)】**
- **正文字数 = 交付物【成稿正文】块内的中文字符数**:每个汉字计 1,字母/数字串计 1,中文标点不计,英文标点不计。
- **计入正文字数**:开头凤头、主体各段正文、结尾豹尾、文内小标题文字。
- **不计入正文字数(逐项排除,核对时必须扣掉)**:`[配图建议:...]` 整块、`> ` 引用块(摘要 / 声明 / 示例标注)、文末风险/免责声明行、【发布前待填/待核】区、金句清单、10 标题清单、排版说明、任何占位符/待核标注。
- **统计方法**:成稿后在内部按上述口径清点字符数(可在思考里算,不写进交付物),**以实际字符数为唯一口径**。Step 7 输出前用此数做自检(见 Step 7)。

**【字数规划(防 1462 字自标 2000 字,Step 4 落笔前必须算)】**

字数短缺不是写完才发现的,是规划时就没分配够。落笔前先按下表把总字数拆到每个结构块,**各段预算加总必须 ≥ 目标字数**:

| 结构块 | 占比 | 2000 字稿(例) | 2500 字稿(默认,例) |
| --- | --- | --- | --- |
| 凤头(开头) | 12% | 240 字 | 300 字 |
| 猪肚主体每段(3-5 段) | 70% ÷ 段数 | 4 段 × 350 = 1400 字 | 4 段 × 437 ≈ 1750 字 |
| 豹尾(结尾+CTA) | 18% | 360 字 | 450 字 |
| **合计(必须 ≥ 目标)** | 100% | **2000 字** | **2500 字** |

写完草稿后**逐块清点实际字符数**(可在思考里逐块累加:开头 X₁ + 段一 X₂ + … + 结尾 Xₙ = X),与预算逐块对账——哪块短了就补哪块,别等到 Step 7 才发现总量不够。**字数缺口的主因几乎总是主体段每段写得太薄**(一段只有 150-250 字):预算 350 字/段的段落,案例 + 观点 + 钩子三要素写满自然到位。

**逐块硬自检算例(取自动态实测"1462 字却自标约 2000 字"事故,照此对账可堵住,不是加一句"注意别超")**:
- 目标 2000 字 / 4 段。预算:凤头 240 + 4×350=1400 + 豹尾 360 = 2000。
- 草稿逐块清点实际正文字符:凤头 ~210 / 段一 ~200 / 段二 ~195 / 段三 ~205 / 段四 ~185 / 豹尾 ~267 → 合计 ~1262(扣掉配图建议块、引用块、文末声明后口径内 ~1462)。
- 对账:主体每段实际 ~200,均 < 预算 350,总缺口 ~540 → **命中"主体段写太薄"主因,Step 7 自检偏差 >10% 必然触发返工**。
- 补写动作:段一~段四各补一层递进案例(每段 +120~140),**不拉长凤头、不堆金句充数**;补后再逐块清点,直至口径内实际 ≥ 2000×0.9=1800。
- 教训固化:任一主体段写到 ~200 字即停 ⇒ 字数必然短缺;预算 350/段的段落,"案例 + 观点 + 钩子"三要素不写满就停,是事故的直接原因。

**另产出 1-2 句摘要**(用于信息流标题下展示):与标题呼应、制造二次悬念,但**不剧透核心结论**,让读者从"被标题吸引→看摘要→点开"形成连贯钩子。摘要单独放在交付物的【摘要】字段。

### Step 5 嵌入金句

在正文基础上,显式嵌入 3-5 句金句(详见 `templates/golden-quotes.md`),放置位置:**小标题 / 段末高潮 / 结尾升华**。在最终交付中单独列出金句清单,标注位置。

### Step 6 排版标注 + 引流设计

- 通读全文,做排版调整:拆长段、加粗关键句、插入 `[配图建议:...]` 节点、检查留白。
- 文末按用户定位设计引流(关注 / 社群 / 课程 / 产品),使用 `templates/formatting-guide.md` 中的话术模板,确保自然过渡。

### Step 7 输出

**【输出前硬性自检(逐条过,不过不交付)】**
1. **字数自检(防"约 N 字"虚标)**:按 Step 4 口径统计实际正文中文字符数 = X,用户要求 = Y。
   - 偏差 ≤ 10%:通过,在【排版说明】里写明"实际 X 字 / 要求 Y 字"。
   - 偏差 > 10% 且**不足**:**必须补写正文**(扩案例 / 加段 / 加金句铺陈),不得直接交付短缺稿。
   - 偏差 > 10% 且**超量**:可适当精简,或在【排版说明】显式告知"实际 X 字 / 要求 Y 字,已超 Y"。
   - **逐块补写指引**:短缺时按 Step 4 的块预算定位缺口块补写(主体段加案例细节/加一层递进/补一段,结尾加铺陈),**禁止用拉长开头或堆金句充数**——开头超 15% 占比会头重脚轻。
   - **铁律:任何情况下都不得在【成稿正文】标题或正文里自标"约 N 字""约 2000 字"**——字数信息只放【排版说明】,且必须给"实际 X / 要求 Y"两个值,让用户自己核对。
2. **正文纯净自检(防占位符/标注污染,兑现"可直接粘贴")**:扫一遍【成稿正文】块,不得出现 `[你的公众号名]`、`(示例数据,发布前核实)`、`(*示例数据...*)` 等任何占位符或待核标注——这些**一律移到顶部【发布前待填/待核】区**。正文必须做到:复制粘贴到公众号后台即可发布,无需用户在正文里再做任何查找替换。
3. **数据真实性自检(防"阿杰式"编造)**:正文中每个带具体数字的人物案例、每个统计数字,必须已用 WebSearch 核实并给来源;**凡未核实的示例数字一律不在正文**——改写成无数字现象叙述,或挪入【发布前待填/待核】区并标 `[示例数据]`;**不得把编造的具体数字当真实案例白描地呈现在正文里**。

最终交付分七块,清晰分隔,方便用户直接复制:

0. **【发布前待填/待核】清单**(放最顶部,集中所有占位符与待核实项;正文里不出现这些东西——这是兑现"可直接粘贴"的关键)。固定格式:

   ```
   【发布前待填/待核】
   - [待填] 文末 CTA:未配置公众号名,已用无占位符话术;如需署名,在 CTA 行补充实际账号名
   - [待核] 开头案例:拟用数据 "……" [示例数据]——发布前替换为真实案例,或删数字保留现象叙述
   - [待核] 段一统计:拟用数据 "……" [示例数据]——发布前用 WebSearch 核实来源或替换
   (无待填/待核项时,本块写"无",不得省略本块)
   ```
1. **摘要**(1-2 句,用于信息流标题下展示)。
2. **封面图建议**(主体 / 情绪 / 文字方案,详见 `templates/formatting-guide.md`)。
3. **成稿正文**(可直接粘贴公众号后台;**纯净:无占位符、无待核标注**,含配图节点标注;字数见【排版说明】)。
4. **10 标题清单**(标注公式 + Top 3 推荐)。
5. **金句清单**(标注嵌入位置)。
6. **排版说明**(加粗策略、配图节点、引流设计要点、**实际字数 vs 要求字数**)。

## 边界情况与避坑

这一节是踩过坑才知道的细节,体现专业度。

- **标题党红线**:公众号对诱导点击、夸大误导有处罚。避免"震惊体"、过度夸张的医疗 / 财经承诺(如"百分百赚钱""包治")。标题公式里"利益承诺"和"争议反常识"尤其要把握度。
- **配图版权**:产出中只给 `[配图建议: ...]` 文字描述,不要假装能生成图片。提醒用户使用正版图库或自制。
- **数据真实性(防"朋友阿杰式"编造,逐条守,硬红线)**:
  - **人物案例的具体数字**(姓名 + 年限 + 金额 + 涨幅 + 结果,如"朋友阿杰,5 年,省 18 万,涨 30%,多赚 6 万"):**一律视为示例数据**,二选一处理——(a) 数字不进正文,连同 `[示例数据]` 标登记到【发布前待填/待核】区(推荐,正文保持纯净);或(b) **改写成无具体数字的现象描写**:"我观察到的现象是,很多省钱成瘾的朋友,几年下来存款增长反而比不过同期换过工作的人"(只描述趋势,不编造数字)。**禁止把姓名+精确数字组合当真实案例白描、不加任何标注地写进正文。**
  - **统计数字**(百分比、中位数、"一份针对 XX 的抽样"结果等):必须经 WebSearch 核实给出来源链接才能进正文;未核实的,连同 `[示例数据]` 标登记到【发布前待填/待核】区;**不得用"一份针对 XX 的抽样"这类伪来源措辞**糊弄,也不得把 `(*示例数据,发布前核实*)` 这类标注留在正文里。
  - **正文里真实数据 vs 示例数据必须视觉区分**:示例数据不得与真实叙述混在同一段不加标注地并列。
  - **BAD→GOOD 改写算例(照此把"阿杰式编造"转成合规正文)**:
    - ❌ BAD(动态实测事故原样):"朋友阿杰给我看过他的账本。连续 5 年,他每月开支控制在 3000 以内……5 年,省下 18 万……如果换一次工作,薪资涨幅哪怕只有 30%,5 年多赚的钱,大概率是这 18 万的两倍。"——姓名+年限+金额+涨幅全是编造,却当真人真事白描、零标注,违反硬红线。
    - ✅ GOOD(合规正文,无编造数字):"我观察到一个现象:身边不少省钱成瘾的朋友,几年下来存款增长反而比不过同期换过一两次工作的人。省下的那笔钱跑不赢通胀,而他们花在'省'上的时间,本来可以用来做更值钱的事。"——只描述趋势,无具体数字,可直接进正文。
    - ✅ 配套【发布前待填/待核】区条目:`- [待核] 开头案例:拟用数据 "5 年省 18 万、换工作薪资涨 30% 多赚约 36 万" [示例数据]——发布前替换为真实案例,或保留上面的无数字现象叙述`。数字不进正文,只进待核区。
  - **示例数据的合规呈现方式(防正文污染,与 Step 7 纯净自检配套)**:`[示例数据]` 标不得出现在【成稿正文】里——**正确做法是正文只写无数字的现象叙述**("我观察到的现象是……""身边不少朋友……"),**具体数字连同 `[示例数据]` 标、核实指引一起放进顶部【发布前待填/待核】区**。该区条目格式:`- [待核] 位置(开头案例/段一统计):拟用数据 "5 年省 18 万、换工作多赚 36 万" [示例数据]——发布前替换为真实案例或核实后的来源数据`。
  - 违反以上任一条即视为产出失败,必须返工。
- **字数与深度平衡**:1500 字以下不适合长文结构,建议改用短推文 skill;5000 字以上要拆系列。
- **敏感话题**:政治、医疗、金融预测、社会热点争议——主动提示风险,语气克制,不给绝对化结论。
- **引流合规**:微信对诱导分享、外部链接跳转有限制。引流话术避免"转发抽奖""必看"等违规词,外部跳转用"阅读原文"而非直接外链。
- **金句堆砌**:金句不是越多越好。3-5 句为宜,全篇都是金句等于没有金句,反而显得油腻。
- **小标题同质化**:3-5 个小标题不要全是"是什么/为什么/怎么办"的流水账,要有信息差和递进感。
- **人设一致性**:读 `_config.json` 中的人设字段,保持语气一致;一个理性干货号突然卖萌、或一个情感号突然讲数据,都会掉粉。

## 配置

读取本目录下 `_config.json`(可选)。**用户不提供就不创建,不要凭空生成配置文件。** 字段如下:

| 字段 | 类型 | 说明 | 默认 |
| --- | --- | --- | --- |
| `account_name` | string | 公众号名称,用于文末引流 | 不填则用通用话术 |
| `persona` | string | 人设描述(理性/感性/幽默/专业),影响语气 | 中性专业 |
| `target_audience` | string | 目标人群画像 | 通用读者 |
| `tone` | string | 整体调性(formal/casual/sharp/warm) | formal |
| `forbidden_words` | string[] | 禁用词清单(合规或品牌要求) | 空 |
| `cta_type` | string | 引流类型(follow/community/course/product) | follow |
| `cta_link_text` | string | 引流话术文案 | 通用模板 |
| `default_word_count` | number | 默认字数 | 2500 |
| `image_style` | string | 配图风格偏好(实拍/插画/极简) | 不指定 |

配置示例(仅供参考,不要主动创建):

```json
{
  "account_name": "某某说",
  "persona": "理性犀利的中年职场观察者",
  "target_audience": "25-35 岁一线城市白领",
  "tone": "sharp",
  "cta_type": "community",
  "default_word_count": 2500
}
```

## 何时用 / 何时不用

**用**:公众号深度长文、品牌内容、知识付费引流文、需要标题和结构方法论支撑的成稿。

**不用**:短推文/朋友圈文案(用短文案 skill)、纯资讯快讯、学术论文、产品说明书、SEO 网文(调性和结构完全不同)。
