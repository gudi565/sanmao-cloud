# 正则速查 & 引擎差异 & 常见范本 & 反模式

## 一、元字符速查

| 写法 | 含义 |
|---|---|
| `.` | 任意单字符(默认不含换行;加 `s` flag 含) |
| `\d` `\D` | 数字 / 非数字 |
| `\w` `\W` | 单词字符[字母数字下划线] / 非 |
| `\s` `\S` | 空白 / 非空白 |
| `[abc]` `[^abc]` | 字符类:任一 / 都不是 |
| `[a-z]` | 范围 |
| `|` | 或 |
| `()` | 分组/捕获 |
| `(?:...)` | 非捕获分组 |
| `(?<name>...)` | 命名捕获(JS/Python3.8+/.NET) |
| `(?P<name>...)` | 命名捕获(Python/PCRE/Go 不支持) |
| `(?=...)` `(?!...)` | 正/负 向先行断言(lookahead) |
| `(?<=...)` `(?<!...)` | 正/负 向后断言(lookbehind,部分引擎不支持变长) |

## 二、量词与锚

| 写法 | 含义 |
|---|---|
| `*` | 0 或多次(贪婪) |
| `+` | 1 或多次(贪婪) |
| `?` | 0 或 1 次 |
| `{n}` `{n,}` `{n,m}` | 恰好 n / 至少 n / n 到 m 次 |
| `*?` `+?` `??` | 非贪婪(惰性)版 |
| `^` `$` | 行首 / 行尾(多行模式下每行的首尾) |
| `\b` `\B` | 单词边界 / 非边界 |
| `\A` `\Z` | 串首 / 串尾(部分引擎) |

## 三、flags(各引擎写法略不同)

| flag | 含义 |
|---|---|
| `i` | 忽略大小写 |
| `m` | 多行(`^$` 匹配每行) |
| `s` | 单行(`.` 匹配换行) |
| `g` | 全局(找全部,JS/grep) |
| `u` | Unicode(JS,处理中文/emoji 必开) |

## 四、各引擎差异表(关键)

| 特性 | JS | Python | Java | Go(RE2) | PCRE(grep -P/php) |
|---|---|---|---|---|---|
| 命名捕获 | `(?<name>)` | `(?P<name>)` | `(?<name>)` | `(?P<name>)` | `(?P<name>)` |
| 向后断言 lookbehind | ES2018+ | 变长不支持 | 固定长度 | ❌ | 变长支持 |
| 回溯引用 `\1` | ✅ | ✅ | ✅ | ❌ | ✅ |
| `s` flag(dot 匹配换行) | ES2018+ | ✅ | ✅(`DOTALL`) | ✅(`(?s)`) | ✅ |
| Unicode 属性 `\p{L}` | 需 `u` flag | ✅ | ✅ | ✅ | ✅ |

**Go (RE2) 特别注意**:为保证线性时间,不支持回溯引用和回溯断言。复杂正则在 Go 里要换写法或用其他库。

## 五、常见校验范本(实用版,非 RFC 严格)

> 注意:这些是"挡明显错误"的实用正则,**不做完整合法性校验**(尤其邮箱/身份证)。严谨场景用专门库。

```
邮箱(实用):  ^[\w.+-]+@[\w-]+(\.[\w-]+)+$
URL:          ^https?://[\w\-._~:/?#\[\]@!$&'()*+,;=%]+$
中国手机:     ^1[3-9]\d{9}$
日期(格式):   ^\d{4}-\d{2}-\d{2}$         (不校验合法性)
时间:         ^([01]\d|2[0-3]):[0-5]\d:[0-5]\d$
整数:         ^-?\d+$
金额(2位小数): ^\d+(\.\d{1,2})?$
中文字符:     [一-龥]              (JS 需 u flag)
强密码:       ^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[^A-Za-z0-9]).{8,}$
IP v4:        ^(\d{1,3}\.){3}\d{1,3}$       (不校验 0-255 范围,要严谨加范围)
```

## 六、反模式与陷阱

### 灾难性回溯(ReDoS)— 生产必防
嵌套量词 + 或重叠的字符类,恶意/超长输入会指数级回溯卡死:
- `(a+)+` 、 `(a|a)*` 、 `([a-zA-Z]+)*`
- 防御:避免重叠量词;对不可信输入设超时;用 RE2 等线性引擎。

### 贪婪误伤
- `".*"` 匹配 `"a" and "b"` 会一路贪到最后的 `"` → 用 `"[^"]*"` 或 `".*?"`。

### 边界缺失
- 校验忘 `^$`:`\d{4}` 会匹配 `abc12345` 里的子串。

### 索引列/性能无关,但:
- 校验正则里用大量 `.*` 会慢,尽量用具体字符类。

### HTML/JSON 解析
- 别用正则解析 HTML/JSON/XML。嵌套结构正则处理不了,用解析器。

### 字符集陷阱
- 中文/emoji 不在 `\w` 范围;JS 要加 `u` flag,否则 `.` 可能切断 emoji。

## 七、EXPLAIN 不了的,用工具

调试正则的工具(建议用户配合):
- regex101.com(在线,可切换引擎,逐字符解释)
- debuggex.com(可视化正则状态机)
- 各语言 REPL 逐步测

## 八、可读性技巧

- 用 `x` flag(PCRE/Python `re.VERBOSE`)允许注释和换行,把长正则拆行写注释。
- 复杂正则用命名捕获组而非编号 `\1`。
- 能用具体字符类 `[^"]` 就别用 `.*`。
