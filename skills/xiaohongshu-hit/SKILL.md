# 小红书爆款笔记

把"写一篇小红书笔记"这件依赖灵感和经验的事,拆成一套可复用的流水线:从选题解析、赛道匹配、标题生成、正文排版、标签配比,到限流词自检,每一步都有明确的检查清单和模板兜底。产出物是一份可直接复制粘贴发布的成稿,而不是"给你点灵感你自己发挥"。

它的价值不在文笔,而在**方法论**——爆款标题7公式、正文"痛-干-真"结构、话题标签3层配比、赛道调性库、限流词清单,这些都是花钱也未必买得到的实操 know-how,全部固化在 templates 里,每次产出都稳定在线。

什么时候用:新产品种草、日常内容更新、投放素材批量生产、蹭热点追话题、冷启动起号。只要最终交付物是"一篇发在小红书上的笔记",就用它。

---

## 核心方法论

以下六条是这个 skill 的判断基准,每一步执行都要对齐它们,而非凭感觉写。

### 1. 标题是第一生产力,没有点击就没有一切

小红书信息流里用户停留决策极短(业内常说只有 1 秒上下),标题(封面上的大字)决定生死。所以**先定标题、再写正文**,正文必须承接标题的承诺,不能标题党挂羊头。标题要用7公式生成5个候选,刻意覆盖不同心理触发点(数字承诺/悬念/对比/反常识/共情),让用户从中选最贴合的一个,而不是只给一个"我觉得不错"的。

### 2. 正文是"痛-干-真"三段式,不是作文

爆款正文本质是**情绪共鸣 + 信息增量 + 信任感**的叠加。钩子开头承接标题(1-2句),痛点段落让读者点头"这说的就是我",干货分点给足价值(3-7条,可截图可收藏),真诚总结/避坑建立信任,最后一句互动引导拉升数据。忌通篇产品参数、忌空洞抒情、忌没有分点的大段文字。

### 3. emoji 是排版工具,不是装饰品

小红书移动端阅读,满屏文字会被划走。emoji 的作用是**做视觉锚点和分段提示**:每段开头一个相关 emoji 标明性质,干货列表用 ✨/💡/✅/⚠️ 做项目符号,适当空行留白。但满屏 emoji 会被判定低质、也显得不专业,单条笔记 emoji 总量默认控制在 8-12 个;仅视觉驱动赛道(美妆/穿搭/美食)且配图密集时,可放宽至 10-12 个(对应配置 high 档)。干货≥5条时,可只在每条开头用1个emoji、信息行不再加emoji,以控总量。

### 4. 标签是流量分配器,要分层而非堆砌

小红书的推荐算法会解析话题标签做内容归类。正确的标签结构是 **1 大词(赛道流量池)+ 2 中词(细分品类)+ 3 长尾(场景/人群/痛点)**,共 5-8 个。只堆大词会被淹没,只堆长尾没流量。`#` 前不加空格、标签不要断行,这是细节但影响收录。

### 5. 赛道调性决定生死,同一套写法不能通吃

美妆要讲成分和真实试色、母婴要讲经验和避坑、数码要讲参数和对比——每个赛道的用户心智和平台流量倾斜完全不同。**写之前先定赛道、锁定调性**,否则写出来的笔记"哪都不像",算法不知道推给谁。详见 `templates/niche-templates.md`。

### 6. 限流词是隐形杀手,发布前必须自检

绝对化词(最/第一/唯一)、医疗承诺(根治/疗效)、导流词(加微信/私信领)、虚假数据,这些词会让笔记被限流甚至违规下架,而且**没有系统提示**——你以为是内容不行,其实是词触雷。所以 Step 5 是硬性步骤,扫描标题+正文,命中即替换。清单见 `templates/limited-words.md`。

## 工作流程

### Step 0 解析输入

从用户消息或 argument 中提取以下要素,缺失的主动追问,不要瞎编:

| 字段 | 说明 | 示例 | 必填 |
|------|------|------|------|
| 主题 | 这篇笔记讲什么 | 敏感肌平价水乳推荐 | 是 |
| 赛道 | 所属内容赛道 | 美妆护肤 | 是(可从主题推断) |
| 目标人群 | 写给谁看 | 学生党/预算100内 | 否,有则更精准 |
| 产品卖点 | 带货时的核心卖点 | 神经酰胺修护、无酒精 | 否,带货必填 |
| 是否带货 | 是否挂车/软广 | 是/否 | 否,默认否 |

同时读取项目目录下的 `CLAUDE.md`(如有项目级偏好)和 `_config.json`(如有自定义配置,字段说明见文末"配置"章节)。不提供就不创建,走默认。

### Step 1 匹配赛道模板

根据主题/赛道,查 `templates/niche-templates.md`,锁定:
- 该赛道的**调性**(如美妆=成分党+真实试色)
- 正文的**侧重段落**(如数码侧重对比表格)
- 该赛道的**避坑点**(如母婴忌贩卖焦虑)

如果主题跨赛道(如"职场妈妈穿搭"),取主赛道调性,副赛道做点缀。

### Step 1.5 爆款校准(可选,但强烈推荐)

这一步把"凭感觉写"升级为"看着市场写",是这个 skill 区别于普通模板的核心卖点。**执行时按下面三条路径依次尝试,绝不允许静默降级**(即跳过后产出物里不留任何标记,让用户以为拿到了"看着市场写"的成果)。

**路径 A(最优)— 实时 WebSearch**

打开 WebSearch,搜 `[赛道] 小红书 爆款 近30天`(如"敏感肌水乳 小红书 爆款 近30天"),抓 3-5 篇高赞笔记的:

- **标题钩子**:它们在用什么句式?(数字承诺?悬念?共情?)→ 校准 Step 2 的标题公式选择,优先用当下正在爆的公式
- **高频标签**:它们在挂哪些话题?→ 校准 Step 4 的标签配比,避免用过气的大词
- **内容空白**:高赞笔记没覆盖的角度 → 本篇可以主打这个差异化

**路径 B(WebSearch 失效时兜底)— 离线校准**

WebSearch 失效(返回 429 / 配额耗尽、无网络、无权限等)时,**不要直接"走默认公式"了事**,改用 `templates/hot-patterns-fallback.md` 的「赛道 × 近期爆款句式」fallback 表按赛道校准标题公式和标签;或请用户粘贴 2-3 篇同类高赞笔记的标题 / 标签做离线校准——比 fallback 表更贴合细分赛道。该表已标注采集时效,平台风向会变,优先级低于实时检索结果但高于默认公式。

**路径 C(兜底也覆盖不到时)— 默认公式 + 显式标注**

若 fallback 表未覆盖该赛道、且用户无法提供参考笔记,才回退到 `title-formulas.md` 的默认 7 公式。此时**必须在交付物顶部按下述硬性规则显式标注**。

校准结果(无论走哪条路径)都要简短列出(2-3 句):本篇选题和标题为什么这么定、参考了什么来源,让用户看到"本篇为什么这么写"。

> ⚠️ **硬性规则 — 校准状态必须对用户透明(不可跳过)**
>
> Step 1.5 走完任一路径,都要在交付物顶部(标题区之前)按 Step 6 / `publish-ready.md` 的「市场校准状态」块标注,三选一:
> - 走路径 A → `✅ 已做实时市场校准(基于近30天 X 篇高赞笔记)`
> - 走路径 B → `⚠️ WebSearch 失效,本次基于兜底句式表 / 用户参考笔记做离线校准,标题/标签非实时数据`
> - 走路径 C → `❌ 本次未做市场校准(实时检索失效 + 无兜底数据),标题/标签基于默认公式`
>
> **绝不允许**:跳过 Step 1.5 后产出物里不留任何标记。这是这个 skill 卖点的底线——卖点可以打折,但不能骗用户。

### Step 2 生成 5 个标题候选(7公式)

调用 `templates/title-formulas.md` 中的**爆款标题7公式**,刻意覆盖不同心理触发点,生成 5 个差异化候选。要求:
- 每个 title 标注所用公式编号(如 `[公式①数字承诺]`)
- 长度建议 14-20 字(小红书标题展示上限约 20 字)
- 必须含一个具体的"钩子词"(数字/对比/反转/结果)
- **自检**:5 个候选不能挤在同一个公式里,至少覆盖 4 种不同公式

把这 5 个候选列给用户选,或让用户指出倾向后微调。

**标题质量自检**(5个候选都过一遍):

| 检查项 | 达标标准 | 不达标处理 |
|--------|----------|------------|
| 长度 | 14-20 字 | 过长精简、过短补信息 |
| 钩子词 | 含数字/对比/反转/结果词至少1个 | 换公式重写 |
| 公式覆盖 | 5个候选至少覆盖4种公式 | 补充未覆盖公式 |
| 承诺可信 | 标题承诺正文能给到 | 调整标题或补正文 |
| 限流词 | 无绝对化/医疗/导流词 | 按 Step 5 替换 |
| 人群精准 | 目标人群能对号入座 | 加人群定语 |

### Step 3 撰写正文(痛-干-真结构)

按以下万能结构成文,emoji 排版规范全程执行:

```
[钩子开头 1-2句] 承接标题承诺,抛出场景或结果
↓
[痛点共鸣] 让读者点头"这就是我"
↓
[干货分点 3-7条] 每条: emoji小标题 + 1-3句说明,可截图可收藏
↓
[真诚总结/避坑] 说点实在话,建立信任
↓
[互动引导] 提一个问题 / 求赞藏
```

emoji 规范:每段开头 1 个相关 emoji;干货用 ✨💡✅⚠️ 做列表符;段间空一行;总量按 `_config.json` 的 `emoji_density`,缺省 8-12 个。正文字数按 `_config.json` 的 `word_count`,缺省 400-800 字(手机两到三屏),太长完播率低。

**正文结构速查**(按赛道微调段落配比):

| 赛道 | 钩子 | 痛点 | 干货条数 | 侧重 |
|------|------|------|----------|------|
| 美妆护肤 | 试色/上脸 | 肤质踩坑 | 3-5 | 成分+对比 |
| 穿搭 | 场景出片 | 身材痛点 | 3-7 | 一衣多穿 |
| 母婴育儿 | 带娃场景 | 踩坑经验 | 3-5 | 避坑为主 |
| 数码科技 | 开箱/参数 | 选购纠结 | 3-5 | 横评表格 |
| 职场成长 | 方法/经历 | 职场困惑 | 3-5 | 方法论+共情 |
| 美食 | 成品诱惑 | 翻车经历 | 4-7 | 步骤分点 |
| 旅游攻略 | 行程/出片 | 踩坑经历 | 4-7 | 攻略实用+小众机位 |
| 学习方法 | 成绩/结果 | 备考焦虑 | 3-5 | 方法+资料 |

干货条数不是越多越好——3-5 条最易读完收藏,超过7条完播率下降。每条都要"能截图",避免无效废话。

**带货=是 时**(对应 Step 0 的"是否带货"字段):干货条目必须覆盖产品核心卖点(来自 Step 0 的产品卖点字段),不能只讲通用科普;文末加购买引导(如"挂车了,需要的姐妹自取");贴士区额外提醒"如为商业合作请开启赞助标注",合规闭环。

### Step 4 生成话题标签 + 封面文案

**话题标签**(3层配比,数量按 `_config.json` 的 `tag_count`,缺省 5-8 个,`#`前无空格):
- 1 个大词:#美妆 / #穿搭 / #美食(赛道流量池)
- 2 个中词:#敏感肌护肤 / #平价水乳(细分品类)
- 3 个长尾:#学生党护肤 / #换季烂脸 / #百元内水乳(场景/人群/痛点)
- tag_count=5时取1+2+2;=6时1+2+3(默认);=7时1+2+4;=8时1+3+4,优先扩长尾层

**封面文案**:
- 大字主标题:建议 8-10 字(移动端超过 10 字会被压缩或换行),高对比(白底黑字 / 莫兰迪底白字),和笔记标题可不同但承诺一致
- 副标题/卖点:1 行,补充主标题
- 视觉建议:色调(如奶油色系)、构图(如产品居中 + 文字上下)、是否需出镜/对比图

### Step 5 限流词自检(硬性步骤)

用 `templates/limited-words.md` 的清单,扫描**标题 + 正文 + 标签**,命中即处理:
- 绝对化词 → 降级表述("最好" → "口碑很好")
- 医疗承诺 → 改成"个人体验/仅供参考"
- 导流词 → 删除或改成"主页有更多"
- 虚假数据 → 删除或标注来源

自检结果要在输出里体现(列出替换了哪些词),让用户安心发布。

### Step 6 输出"可复制发布版"

按 `templates/publish-ready.md` 的分块格式输出:
1. **标题区**:用户选定(或推荐)的 1 个 + 备选 4 个清单
2. **正文区**:完整 emoji 排版正文,可直接复制
3. **标签区**:成组话题标签
4. **封面区**:大字主标题 + 副标题 + 视觉建议
5. **小贴士**:发布时间/互动话术/配图数量建议

所有内容分块清晰,用户复制即用,不需要二次整理。

## 边界情况与避坑

- **平台差异**:本 skill 针对小红书(图文为主、移动端、强种草)。同样内容发抖音要改短口播脚本、发公众号要加长论述,不能直接套用。
- **医疗/金融/保健品类**:高度敏感,即使是个人分享也容易触雷。这类赛道正文必须加"个人体验,不构成专业建议",且禁用一切疗效/收益承诺词,详见限流词清单。
- **带货/软广标注**:小红书官方要求商业合作笔记开启"赞助"标识。skill 不替用户做合规判断,但在输出小贴士里提醒一句"如为商业合作请开启赞助标注"。
- **热点蹭流量**:蹭热点要快但不能硬蹭,主题和热点必须有真实关联,否则会被判低质。建议在钩子开头自然带出热点,主体仍讲自身干货。
- **冷启动新号**:新号前 5-10 篇笔记权重低,建议聚焦单一赛道打标签,不要一篇美妆一篇数码来回跳,会让算法无法给账号定位。
- **不适用场景**:纯文字深度长文(>1000字)、纯新闻资讯、企业对企业的内容,这些不是小红书的内容形态,用本 skill 产出会"不对味"。
- **emoji 过载翻车**:常见误区是以为 emoji 越多越"小红书",实际满屏 emoji 会被判定低质营销。控制在 8-12 个、每段开头 1 个、干货用列表符,足矣。
- **标题党反噬**:标题承诺了"3天见效",正文必须给到对应干货,否则用户点进来划走,完播率崩,算法反而降权。标题和正文是契约关系。

## 配置

本 skill 支持可选的 `_config.json`(放在项目根目录),用户不提供就不创建,走默认值。字段如下:

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `default_niche` | string | 无 | 默认赛道,如"美妆",省去每次指定 |
| `tone` | string | "真诚种草" | 整体语气:真诚种草/专业测评/闺蜜安利 |
| `emoji_density` | string | "medium" | emoji 密度:low(6-8个)/medium(8-12)/high(10-12,仅视觉类赛道适用) |
| `word_count` | string | "400-800" | 正文字数区间 |
| `tag_count` | number | 6 | 话题标签数量,5-8 |
| `avoid_soft_ad` | boolean | true | 是否回避软广感强的表述 |
| `brand_words` | array | [] | 品牌必带词,如["成分","无添加"] |
| `forbidden_words` | array | [] | 用户额外想避开的词 |

读取逻辑:存在 `_config.json` 则合并到默认配置;字段缺失走默认;格式错误则忽略并提示用户。

## 产出质量自检清单

交付前逐项打钩,任何一项不过就回去补,不带着瑕疵发布:

- [ ] 交付物顶部已标注「市场校准状态」(✅实时校准 / ⚠️离线兜底 / ❌未校准+默认公式),三选一,绝不静默降级
- [ ] 标题 5 候选已生成,覆盖≥4种公式,长度达标
- [ ] 正文含"钩子-痛点-干货-总结-互动"完整五段
- [ ] 干货分点 3-7 条,每条有 emoji 小标题,可截图
- [ ] emoji 总量 8-12,段间有空行,无满屏 emoji
- [ ] 话题标签 5-8 个,含1大词+2中词+3长尾,`#`前无空格
- [ ] 封面大字主标题 8-10 字,有视觉建议(色调/构图)
