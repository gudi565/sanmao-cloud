# 思维导图

你的任务:把一团东西(主题、文档、想法、问题)整理成**层级清晰、互不重叠、穷尽覆盖**的思维树,让用户一眼看清结构和全貌。

核心方法:**MECE(互斥穷尽)** 是骨架。一级分支要 mutually exclusive、collectively exhaustive;子节点逐层展开,深度可控。

输出格式统一用 **markdown 缩进**(兼容 Markmap / 幕布 / Xmind / MindNode 等几乎所有脑图工具),用户直接复制就能可视化。

## 何时用

- 把一个主题/领域拆成知识树。
- 把一篇长文档/一本书/一份笔记结构化成脑图。
- 头脑风暴时发散维度再收敛。
- 规划一个项目/产品的结构。
- 把混乱的想法理清。

## 何时别用

- 画流程/时序/架构图 → 用 `diagram` / `genskills--architecture-diagram`(那些是流程,不是层级)。
- 做图表/数据可视化 → 用 `dataviz`。
- 总结一篇文章的要点 → 用 `summarize`(脑图侧重结构,总结侧重内容压缩)。
- 项目排期/甘特 → 用 `roadmap-planning`。

## 四条核心纪律

1. **MECE 是骨架。** 同层节点之间不重叠、合起来覆盖父节点的全部。这是脑图区别于"随便列一堆"的关键。
2. **一次只展开一个维度。** 同一层级的节点要处在同一个分类维度上(比如都是"按阶段分",或都是"按角色分"),不要混维度。
3. **深度可控,别碎。** 一般 3-4 层够用。太深=碎,太浅=没价值。叶子节点要是一个可理解的完整概念。
4. **节点是短语不是句子。** 每个节点 ≤ 10 字,提炼关键词;详细说明放到叶子节点的括号里,不挤进结构。

## 工作流

### 1. 定根节点

一句话/一个词,说明这棵树是关于什么的。够具体,别太泛。("产品设计流程" > "产品")

### 2. 识别主分支(一级,最关键)

这是脑图成败所在。问自己:**这个主题可以从哪几个正交维度拆?** 选最贴合用户目的的那个维度。

常见拆解维度:
- **按流程/时间**:阶段 1 → 阶段 2 → ...(适合"怎么做"的主题)
- **按组成/分类**:A 类、B 类、C 类(适合"是什么"的主题)
- **按因果/层次**:原因 / 现象 / 对策(适合分析型)
- **按优先级/重要性**:核心 / 重要 / 可选
- **按主体/角色**:用户侧 / 商家侧 / 平台侧

**MECE 自检**:一级分支两两重叠吗?合起来漏了什么?不通过就重构。

### 3. 逐层展开

对每个一级分支,用同样的逻辑往下拆。**保持同层同维度**(别在"按阶段分"的一级下面突然"按角色分")。

### 4. 控制规模

- 一级分支建议 3-7 个(少于 3 太单薄,多于 7 考虑再分组)。
- 同父节点子项建议 2-6 个。
- 总深度 3-4 层,除非用户要更深。

### 5. 输出 + 可视化建议

输出 markdown 缩进格式(见下)。给一句"如何变成图"的提示(Markmap 在线粘贴即出图 / XMind 导入 markdown)。

## 输出格式

标准 markdown 缩进(用 `- ` 列表):

```
# 根节点主题

- 一级分支 A
  - A1
    - A1.1
    - A1.2
  - A2
- 一级分支 B
  - B1
  - B2
- 一级分支 C
  - ...
```

附:
- **拆解维度说明**(一句话:这棵树的主维度是什么)。
- **可视化建议**(粘贴到 markmap.js.org/repl/ 即出图;或 XMind→文件→导入 Markdown)。

## 失败模式(别犯)

- ❌ **非 MECE**:分支重叠(同一概念出现在两个分支下)或遗漏(合起来不全)。
- ❌ **混维度**:同一层级有的按时间、有的按角色,结构混乱。
- ❌ **流水账当脑图**:把文章段落原样列成树,没有抽象成结构。
- ❌ **太深太碎**:展开 6 层,叶子全是碎词,失去鸟瞰价值。
- ❌ **节点太长**:每个节点写一整句话,树变得不可读。
- ❌ **硬塞平衡**:为了对称硬凑分支数量,实际没那么重要的内容也单列。

## 不同场景的差异化

- **从文档/书做脑图**:先抓作者的章节结构(通常已是好骨架),再按 MECE 补漏、删冗。
- **主题发散(头脑风暴)**:先穷尽再归类——先列所有相关点,再分组找维度,最后成树。
- **决策/规划型**:一级常是"目标—现状—方案—风险"或"按优先级"。
