# 改写润色

你的任务:把一段文字改成用户想要的**语气/长度/受众/文体**,同时**忠于原意**。不是改内容,是改"怎么说"。用户最常要的是:更口语 / 更正式 / 更精简 / 去 AI 味 / 换受众。

核心纪律:**先问清目标维度,改对方向;改完字数/要点不丢;不动用户的事实和立场。**

## 何时用

- 润色:让文字更顺、更像人话。
- 调语气:口语 ↔ 正式 ↔ 专业 ↔ 活泼。
- 精简:压缩长度,保要点。
- 换受众:同一件事给老板/客户/小白/同行不同版本。
- 去 AI 味:去掉"综上所述""首先其次"那种机械感。
- 改文体:邮件 ↔ 消息 ↔ 文档 ↔ 社交文案。

## 何时别用

- 跨语言翻译 → 用 `translate`。
- 学术降重(过查重) → 用 `降重`(有专门的 bigram 校验管线)。
- 从零写长文 → 用 `write-blog`。
- 总结压缩成要点(不要保留原文全貌) → 用 `summarize`。
- 改的是代码不是文字 → 不是这个 skill。

## 改写的六个维度(先定方向,再动手)

用户说"润色一下"往往不够具体。先确认/推断这几个维度:

| 维度 | 选项 |
|---|---|
| 语气 | 口语 / 正式 / 专业 / 活泼 / 严肃 / 友好 |
| 受众 | 老板 / 客户 / 同事 / 小白 / 同行 / 大众 |
| 长度 | 更短 / 保持 / 更长(展开) |
| 文体 | 邮件 / 消息(IM)/ 文档 / 社交文案 / 汇报 |
| 强度 | 轻微润色(保留个人风格)/ 大改(重写表达) |
| 必须保留 | 术语 / 数字 / 专有名词 / 立场 |

说不清就按最可能的来并标注,或给两个版本让用户选。

## 五条核心纪律

1. **忠于原意。** 改的是"怎么说",不是"说什么"。事实、数字、立场、专有名词不动。要补/改信息先问。
2. **先定维度再改。** 不知道往哪个方向改,改了也白改。先确认目标语气/受众/长度。
3. **保信息量。** 精简≠删要点。压缩冗余表达,不压缩内容。改完要点数 ≥ 原文。
4. **去 AI 味优先。** 现代文字最大的毛病是机械感,先杀"首先其次最后""综上所述""毋庸置疑"。
5. **保留个人声音。** 轻度润色时,别把用户的个人风格/口头禅抹平成"标准但无趣"。

## 工作流

### 1. 读原文,提炼"骨架"

先抓:这段话的核心信息和要点是什么?改写后这些**一个都不能丢**。

### 2. 确认目标维度

用户说了就照办;没说就按最可能的推断 + 标注,或给两个版本。

### 3. 按维度改写

常见改写动作:

- **精简**:删冗词(的/了/进行+动词)、合并重复、长句拆短、删正确的废话。
- **口语化**:用短句、加语气词、用日常词替书面词("获悉"→"知道")。
- **正式化**:用完整句、规范用词、去口语语气词、结构更严谨。
- **专业感**:用领域准确术语(但要确认受众懂)、逻辑链清晰。
- **去 AI 味**:删机械连接词、删空泛形容词、改"首先其次"为自然过渡、删"综上所述"式结尾。
- **换受众**:调整术语密度、例子、详略(给老板要结论先行,给同行要细节)。

### 4. 自检

- 要点有没有丢?(对照原文骨架)
- 语气对了吗?(读出声感受)
- 有没有夹带我没核实的信息/观点?
- 有没有引入 AI 味?
- 数字/术语/专有名词原样保留?

### 5. 输出 + 说明改了什么

给改写版,并用一两句说明主要改了什么方向(让用户知道改在哪、能否接受)。

## 不同场景的差异化

| 场景 | 改写侧重 |
|---|---|
| 工作消息/IM | 短、直接、结论先行、有行动点 |
| 邮件 | 礼貌但简洁、结构清晰、称呼落款 |
| 汇报/周报 | 结论先行、数据支撑、去掉情绪化表达 |
| 社交文案 | 有钩子、短句、口语、适合阅读节奏 |
| 技术文档 | 准确、无歧义、术语统一、删修辞 |
| 对外文案 | 受众视角、利益点清晰、避免内部黑话 |

## 失败模式(别犯)

- ❌ **改变原意**:改着改着加了原文没有的信息或观点。
- ❌ **要点丢失**:精简把内容也压没了。
- ❌ **方向没问清就大改**:用户只想顺一下,你给重写了。
- ❌ **过度标准化**:把有特点的表达抹平成通用无聊腔。
- ❌ **引入 AI 味**:本想润色,结果更"AI"了(排比、对仗、空形容词)。
- ❌ **数字/术语被改**:把专有名词换了说法、数字单位弄错。
- ❌ **只给一个版本不说明**:用户不知道你改了啥、能不能用。

## 多版本策略

当目标不明确或多种需求合理时,给 2 个版本让用户选方向,而不是赌一个:

```
版本 A(更精简口语):
  ...

版本 B(更正式):
  ...
```

然后问"哪个方向对?我再按这个细化"。

## 输出格式

1. **改写版**(主体)。
2. **改了什么**(一两句:主要动作是精简/换语气/去 AI 味等)。
3. **(可选)备选版本**(目标不明确时给第二方向)。
4. **(可选)存疑/确认**:改写中我做的假设或需要用户确认的地方。
